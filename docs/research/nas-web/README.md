# 小说到成片 NAS Web 系统方案

日期：2026-11-08。源码基线：`3cee8c26d3032da6cc0654423980a0bbc42f995f`，package.json 版本 1.4.0。调研开始时工作树干净。

本目录是基于本地源码检查的设计提案，不代表功能已经实现或通过 Linux/NAS 验证。本次仅增加文档，没有修改应用代码，也没有安装依赖、运行构建或模型调用。

## 总体范围

用户已确认同一套系统覆盖长篇小说、剧本改编、短剧与漫剧制片，包含分镜、素材、剪辑、成片和分阶段交付的 3D 导演台。小说工作区为第一阶段，完整范围以 [全流程设计](06-novel-to-film.md) 为准。

## 结论

可行，推荐保留 React/CodeMirror 界面、写作领域规则和仓储，抽离 Node.js 服务端，新增浏览器启动、HTTP/SSE、用户会话、项目上下文、自动保存与移动布局。不能只将 Electron 打包进 Docker，也不能直接公开原 IPC。

首版目标：单用户、多设备、多作品；电脑、iPad、手机访问 NAS，同一作品以服务端为正式数据源。保留草稿、恢复候选、修稿、定稿的区别。暂不实施多人实时协同、完整离线作品管理和在线发布。

## 核心决策

- Linux 文件层是已确认的阻塞项，需要实现并测试，不再仅列为“可能存在兼容风险”。
- 生成任务已有持久化账本和来源约束；复用它们，新增服务端调度与可重连订阅，不平行重造一套生成事实源。
- 前端仍承担部分工作流编排；必须将无用户交互的完整执行链迁入服务端，不能只迁移模型请求。
- 自动保存采用本地草稿、停止输入触发、固定周期兜底、后端版本校验及幂等提交的组合。
- 首版单应用实例、SQLite 项目分库。SQLite 位于 NAS 本机持久化卷，不放在另一个主机的 SMB/NFS 挂载上供多进程共享写入。
- 先完成一条真实闭环原型，再确定完整功能排期。
- 结合 Reveric 时采用设计与能力整合，继续使用 Pagekin Web 单一主体；新增统一领域命令、事务事件和跨设备审批，不直接合并两套应用与数据库。

## 已确认部署环境

- CPU：Intel J5005，x86-64；容器目标平台为 `linux/amd64`，不是 32 位 x86。
- NAS 系统：fnOS（用户已确认，具体版本待补充）。
- 部署方式：Docker Compose；首版交付 Compose 配置、环境变量示例、持久化目录及升级/恢复说明。
- 首版只要求上述平台验证，ARM64 镜像延后，不作为本次验收条件。
