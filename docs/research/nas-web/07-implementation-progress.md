# Web 小说工作区实施进度

本页记录开发分支上的实现与验证。架构设想仍见 [系统设计](02-system-design.md) 和 [小说到成片设计](06-novel-to-film.md)。配置与使用以 [Web 工作区 README](../../../web-novel/README.md) 为准。

## 接续摘要

- 目标是同一作品空间内从长篇小说走到短剧或漫剧成片，按小说、剧本与分镜、素材与剪辑、渲染与导演台逐步交付。Pagekin 提供小说领域基础，Reveric 提供剧本与制片流程的实现参考。
- 部署目标是 Intel J5005 的 x86-64 fnOS NAS，使用 Docker Compose，在电脑、iPad 和手机浏览器工作。用户已在 fnOS 部署过旧版。代码在 `ChenMartin/Pagekin` 的 `codex/web-novel-fnos` 分支，Web 应用位于 `web-novel/`。
- 小说编辑采用本机草稿与 NAS 自动同步。剧本输入自动暂存，作者点保存后提交。两边均校验版本。模型生成先进入候选，正文应用、剧本确认与小说定稿由作者完成。
- 当前开发重点是补齐 Web 小说工作流。手工剧本改编已可用，后续制片从定稿生成 AI 分集与剧本候选，再从已确认场次生成镜头表与分镜。

## 交付基线

| 范围 | 当前状态 |
| --- | --- |
| 离线候选版 | `v0.2.0-rc.1` 面向 Linux amd64，使用 SQLite schema 11，包含小说与剧本改编工作区。 |
| CodeMirror | 开发分支接入 CodeMirror 6，普通编辑器仍可用于兼容排查。两种编辑模式通过 Edge 回归。 |
| 语义检索 | schema 6 增加按作品保存的参考资料索引。用户显式启动索引，可续跑成功批次之外的资料，并选中命中片段。模拟向量服务、浏览器和 Linux 容器回归通过。 |
| 写前细纲 | schema 7 保存正文任务选择的细纲。正文、作者要求和上下文一致时才允许引用；审稿不接收细纲。任务与候选历史可备份为独立副本。 |
| 结构化审稿 | 报告逐条记录问题、严重程度、引文和改法。复用正文历史保存审稿版本，可定位唯一匹配的引文并将勾选项加入修稿要求。 |
| 按段接受修订 | 已完成的修稿可分页对比，单独勾选插入、删除或替换。服务端合并选中改动，保留未选原文和合并前的版本。 |
| 批量写作 | schema 8 保存批次队列。按章号串行生成候选，暂停、失败或服务重启后可手动继续。 |
| 写作 Skill | schema 9 保存作品级提示词库和阶段绑定。模型预览、生成、候选校验与作品备份使用同一绑定。 |
| 分段续跑 | schema 10 保存原生成输入和候选来源。单章可手动从完整句段续写，批次继续时可复用资料一致的中断候选。 |
| 剧本改编 | schema 11 新增短剧／漫剧改编、季号和分集、结构化场次编辑、来源追踪、确认及 Markdown 导出。 |
| Web 创作导航 | 开发分支加入书房、作品概览、四阶段切换、章节状态筛选、蓝图与正文互跳、作品级运行中心、专注模式和本机外观设置。 |
| 作品写作目标 | schema 12 保存题材、受众、语言和篇幅目标，支持跨设备版本校验、候选来源校验和作品 JSON 迁移。桌面导入可填充对应字段。 |
| AI 规划与选段编辑 | 设定、人物和单章蓝图可生成候选。正文可对选区续写、润色、扩写和改成对话，应用前核对选区原文与来源。 |
| 架构模块 | 故事前提、人物群像、世界观和情节大纲各有 Markdown 模板与可独立选择的 AI 规划范围。 |
| 批量蓝图 | schema 12 复用写稿队列，按 1–20 章的范围建立空蓝图、串行生成、跳过已有内容、暂停与继续。 |
| 正文导出 | 合并 Markdown、UTF-8 TXT、分章 Markdown ZIP。可选择最新定稿快照或 NAS 当前正文。 |
| 参考小说 | schema 13 新增独立参考书架、TXT／Markdown 按章导入、范围拆解、覆盖跟踪、整书归纳，以及经作者编辑确认的仿写 Skill。 |
| 人物连载 | schema 14 保存开篇与定稿后人物状态、有向关系和旧定稿记录。支持按章查看与筛选关系，写作时只使用之前有效的记录。 |
| 人物变化候选 | schema 15 支持从定稿对单个人物提取状态变化，校验连续引文，逐条填入并由作者保存。已采用的原文引证随人物状态备份。 |
| 桌面人物历史 | schema 16 保存原桌面人物事件、状态时点、有向关系及来源引用。读取写稿上下文时按生效章折叠，区分当前定稿和被替换来源。 |
| 长篇进度 | 按章查看蓝图、正文、重开定稿和线索，支持分页跳章、首个未定稿定位，以及进入线索编辑处理跨章提醒。 |

目前实现采用独立的 Node.js 服务、浏览器前端和 Web SQLite 库。它沿用了桌面项目的领域语义，并通过转换接口导入桌面作品。最初提案中共享 Electron 仓储和直接接入桌面执行器的内容仍是设计目标。

## 写前细纲流程记录

1. 对照上游的 [写前细纲合同](../../../src/shared/draft-short-outline.ts) 和 [生成正文命令](../../../src/services/workflows/commands/generate-draft.command.ts)，保留细纲与作者事实、实际前文、正文候选的边界。
2. 增加独立细纲任务，按章节版本、源资料和本次输入绑定。写稿时由作者选用细纲，正文候选需要另行确认。
3. 在原有任务历史与作品 JSON 备份中保留细纲关系。整库备份依旧适合迁移运行库；JSON 恢复时会生成独立的作品和任务 ID。
4. 更新中英文仓库首页、Web 使用说明与文档索引，区分历史候选版、当前开发源码和后续全流程设计。

## 结构化审稿流程记录

1. 对照桌面版的逐条审稿和作者确认流程，在 Web 版记录问题、引文、原因及建议改法。审稿引文必须对应实际待审正文。
2. 在创建审稿任务的事务中保存正文快照。报告读取时按任务基准版本校验引文，作品 JSON 恢复后仍能核对。格式不符的输出保留为可选中的纯文本。
3. 编辑器支持原文定位和勾选意见。当前文档与审稿版本一致时，可将所选意见加入修稿要求。修稿仍经候选预览与作者确认。

## 修稿合并流程记录

1. 按正文行对齐两份文本，保留未选部分的原始字符。连续拆段或合段可作为同一项比较。窄屏可分页浏览，勾选状态随页保留。
2. 合并复用章节版本和生成资料校验，使用事务写入正文历史和候选应用状态。相同选择可以安全重试，已应用的候选不能再次接受不同改动。

## 批量写作流程记录

1. 批次保存章节版本和通用作者要求，开始生成前重新核对章节。单章任务和批次共享一个模型执行槽位。
2. 相邻上一章候选以未定稿资料的身份进入提示词，并参与后续候选的来源校验。应用候选由作者逐章确认。
3. 暂停或重启保留部分输出和已完成候选。手动继续会重试未完成的章节，跳过期间已经编辑或定稿的章节。

## 写作 Skill 流程记录

1. 浏览器读取作者选取的 UTF-8 文件，预览后将文本保存到作品。分阶段绑定使用版本校验，可检查其他设备提交的变更。
2. 提示词纳入模型输入预算和候选来源校验。写前细纲及正文可以使用各自的 Skill；批次创建时记录写稿 Skill，绑定变化会暂停队列。
3. 作品 JSON 恢复时重建 Skill 库和绑定，并生成独立标识。

## 分段续跑流程记录

1. 从已保存的输出找到最近的段落或句末边界。模型只收到候选末尾作为续写锚点，服务端保留完整前缀，合并后生成独立候选。
2. 校验原任务的正文版本、作者要求和来源绑定。相同续跑请求可安全重试，原任务的部分输出可从历史查看。
3. 批次手动继续时优先复用完整句段。若来源发生变化则从当前资料重新生成该空白章节。跨设备修改过的目标章节继续跳过。

## 剧本改编流程记录

1. 参照 Reveric 的系列、分集和场次元素约束，在同一 Web 作品下实现改编项目。场次和元素使用稳定 ID，以集为单位保存结构化快照。
2. 分集绑定具体小说定稿版本，场次可关联本集的章节，人物对白可引用同一作品中的人物卡。小说当前正文变化后标记来源变化，并保留原定稿引用。
3. 输入暂存于 IndexedDB，点击保存后提交至 NAS。服务端按集校验版本，并原子保存快照与幂等记录。确认后的剧本可重开，剧本历史和引用可随作品 JSON 恢复。

## 参考小说流程记录

1. 参考书、原文章节和拆解任务使用独立数据表。按文件顺序编号，保留原章号。小说正文和日常写作的上下文不自动读取这些数据。
2. 每次选定连续 1–20 节。预览与实际任务使用相同的字符预算。服务端验证模型回传的全部章节位置，格式有误的结果保留原输出供核对。
3. 全书位置均有成功报告后，整书归纳为每个位置选用最近的成功报告，并记录所用任务。导出的作品 JSON 在恢复副本时重建报告关系。
4. 仅将可迁移写法带入 Skill 编辑表单。作者可以改写、安装并选择绑定阶段。参考书和模型输出仍可在书架查看。

## 验证与后续

rc.2 的 Windows 和 `linux/amd64` 容器 HTTP 回归各通过 4 项。Edge 普通编辑器和 CodeMirror 都验证了窄屏修稿、批量写作、Skill 绑定和分段续跑。Compose 隔离卷验证了 schema 5 到 10 的升级及正文、历史与备份恢复。模型调用使用模拟端点。

`v0.2.0-rc.1` 的 Windows 和 `linux/amd64` HTTP 回归各通过 4 项，覆盖来源变化、并发保存、剧本版本恢复和作品 JSON 引用重建。Edge 两种编辑模式均通过窄屏、刷新恢复本机剧本、确认和查看历史。Docker Compose 在隔离卷上通过了 schema 10 到 11 的迁移、重启、在线备份和独立卷恢复，确认了剧本历史、状态和原定稿引用。

`0.2.0-dev.2` 的 Windows 和 `linux/amd64` HTTP 回归覆盖规划范围和候选、选段应用、批量蓝图、写作目标及导出。普通编辑器和 CodeMirror 的 Edge 回归覆盖对应菜单和操作，包括从模板新建世界观并确认候选。使用 RC.1 镜像和隔离 Docker 卷验证了 schema 11 到 12 的升级，原定稿和可继续的写稿批次保留。文字生成测试使用模拟模型。

`0.2.0-dev.3` 的 Windows 与 `linux/amd64` HTTP 回归、Edge 两种编辑模式均通过。覆盖参考书导入、项目隔离、取消拆解、报告校验、整书归纳、手动安装仿写 Skill 和备份恢复。使用 RC.1 镜像在隔离 Docker 卷验证 schema 11 到 13 的迁移，原定稿、暂停后可继续的旧批次和新拆解任务的中断输出均保留。生成测试使用模拟模型。

`0.2.0-dev.4` 的 Windows 和 `linux/amd64` HTTP 回归覆盖人物状态、并发保存、重新定稿后的失效与历史查看，以及 JSON 恢复后的关系与版本映射。Edge 两种编辑模式均通过人物卡入口、关系编辑及有向关系查看。隔离 Docker 卷按 schema 11、13、14 顺序升级，保留原定稿、人物卡和参考书，并验证了新版人物记录重启恢复。生成测试使用模拟模型。

`0.2.0-dev.5` 的 Windows 和 `linux/amd64` HTTP 回归覆盖重开稿与定稿的区分、唯一／重复／缺失引文、候选跨人物和定稿版本校验、逐字段保存和 JSON 恢复。Edge 两种编辑模式覆盖提取、选择、保存及运行中心重开候选。隔离 Docker 卷从 schema 14 升到 15 后保留原人物记录和新引文。生成测试使用模拟模型。

`0.2.0-dev.6` 的 Windows 和 `linux/amd64` HTTP 回归覆盖 schema 8 状态基线和 schema 9 事件导入、作者与派生事件的不同生效章、定稿替换、关系删除与 JSON 副本的引用重建。Edge 两种编辑模式均验证桌面历史和引文显示。隔离 Docker 卷从 schema 15 升到 16 后保留原人物状态，桌面事件重启后仍可查看。

`0.2.0-dev.7` 的 Windows 和 `linux/amd64` HTTP 回归覆盖缺章、空蓝图、重开定稿、写作目标和四类线索提醒。Edge 两种编辑模式均通过分页、跳章、从提醒进入线索编辑、保存后返回原页及打开正文的流程。沿用 schema 16。
