# Web 小说工作区实施进度

本页记录开发分支上的实现与验证。架构设想仍见 [系统设计](02-system-design.md) 和 [小说到成片设计](06-novel-to-film.md)。配置与使用以 [Web 工作区 README](../../../web-novel/README.md) 为准。

## 接续摘要

- 目标是同一作品空间内从长篇小说走到短剧或漫剧成片，按小说、剧本与分镜、素材与剪辑、渲染与导演台逐步交付。Pagekin 提供小说领域基础，Reveric 提供剧本与制片流程的实现参考。
- 部署目标是 Intel J5005 的 x86-64 fnOS NAS，使用 Docker Compose，在电脑、iPad 和手机浏览器工作。用户已在 fnOS 部署过旧版。代码在 `ChenMartin/Pagekin` 的 `codex/web-novel-fnos` 分支，Web 应用位于 `web-novel/`。
- 小说编辑采用本机草稿与 NAS 自动同步。剧本输入自动暂存，作者点保存后提交。两边均校验版本。模型生成先进入候选，正文应用、剧本确认与小说定稿由作者完成。
- 小说、剧本、分镜和剪辑工作区已可串联使用。样片支持静帧运动、三类音频轨道和独立定时字幕。后续扩展画面效果、代理预览和导演台。

## 写前细纲流程记录

1. 对照上游的 [写前细纲合同](../../../src/shared/draft-short-outline.ts) 和 [生成正文命令](../../../src/services/workflows/commands/generate-draft.command.ts)，保留细纲与作者事实、实际前文、正文候选的边界。
2. 增加独立细纲任务，按章节版本、源资料和本次输入绑定。写稿时由作者选用细纲，正文候选需要另行确认。
3. 在原有任务历史与作品 JSON 备份中保留细纲关系。整库备份依旧适合迁移运行库；JSON 恢复时会生成独立的作品和任务 ID。
4. 更新中英文仓库首页、Web 使用说明与文档索引，区分历史候选版、当前开发源码和后续全流程设计。

## 结构化审稿流程记录

1. 对照桌面版的逐条审稿和作者确认流程，在 Web 版记录问题、引文、原因及建议改法。审稿引文必须对应实际待审正文。
2. 在创建审稿任务的事务中保存正文快照。报告读取时按任务基准版本校验引文，作品 JSON 恢复后仍能核对。格式不符的输出保留为可选中的纯文本。
3. 编辑器支持原文定位和勾选意见。当前文档与审稿版本一致时，可将所选意见加入修稿要求。修稿仍经候选预览与作者确认。

## 修稿合并流程记录

1. 按正文行对齐两份文本，保留未选部分的原始字符。连续拆段或合段可作为同一项比较。窄屏可分页浏览，勾选状态随页保留。
2. 合并复用章节版本和生成资料校验，使用事务写入正文历史和候选应用状态。相同选择可以安全重试，已应用的候选不能再次接受不同改动。

## 批量写作流程记录

1. 批次保存章节版本和通用作者要求，开始生成前重新核对章节。单章任务和批次共享一个模型执行槽位。
2. 相邻上一章候选以未定稿资料的身份进入提示词，并参与后续候选的来源校验。应用候选由作者逐章确认。
3. 暂停或重启保留部分输出和已完成候选。手动继续会重试未完成的章节，跳过期间已经编辑或定稿的章节。

## 写作 Skill 流程记录

1. 浏览器读取作者选取的 UTF-8 文件，预览后将文本保存到作品。分阶段绑定使用版本校验，可检查其他设备提交的变更。
2. 提示词纳入模型输入预算和候选来源校验。写前细纲及正文可以使用各自的 Skill；批次创建时记录写稿 Skill，绑定变化会暂停队列。
3. 作品 JSON 恢复时重建 Skill 库和绑定，并生成独立标识。

## 分段续跑流程记录

1. 从已保存的输出找到最近的段落或句末边界。模型只收到候选末尾作为续写锚点，服务端保留完整前缀，合并后生成独立候选。
2. 校验原任务的正文版本、作者要求和来源绑定。相同续跑请求可安全重试，原任务的部分输出可从历史查看。
3. 批次手动继续时优先复用完整句段。若来源发生变化则从当前资料重新生成该空白章节。跨设备修改过的目标章节继续跳过。

## 剧本改编流程记录

1. 参照 Reveric 的系列、分集和场次元素约束，在同一 Web 作品下实现改编项目。场次和元素使用稳定 ID，以集为单位保存结构化快照。
2. 分集绑定具体小说定稿版本，场次可关联本集的章节，人物对白可引用同一作品中的人物卡。小说当前正文变化后标记来源变化，并保留原定稿引用。
3. 输入暂存于 IndexedDB，点击保存后提交至 NAS。服务端按集校验版本，并原子保存快照与幂等记录。确认后的剧本可重开，剧本历史和引用可随作品 JSON 恢复。

## 参考小说流程记录

1. 参考书、原文章节和拆解任务使用独立数据表。按文件顺序编号，保留原章号。小说正文和日常写作的上下文不自动读取这些数据。
2. 每次选定连续 1–20 节。预览与实际任务使用相同的字符预算。服务端验证模型回传的全部章节位置，格式有误的结果保留原输出供核对。
3. 全书位置均有成功报告后，整书归纳为每个位置选用最近的成功报告，并记录所用任务。导出的作品 JSON 在恢复副本时重建报告关系。
4. 仅将可迁移写法带入 Skill 编辑表单。作者可以改写、安装并选择绑定阶段。参考书和模型输出仍可在书架查看。

## 剧本与分镜阶段

分集提案关联选定的小说定稿，勾选后在同一事务中创建剧本草稿。剧本候选使用分集提纲和已选小说来源，人物序号映射到本作品人物卡。候选采用检查剧本基准版本。

分镜从已确认的剧本修订版建立。手工和 AI 镜头共用同一数据模型。按场采用候选时保留其他场次的镜头。剧本更新后可查看受影响的场次，旧分镜版本可读取与导出。镜头及其来源随作品 JSON 和整库备份恢复。 [剧本与分镜阶段开发清单](09-screenplay-storyboard-checklist.md)
