# 书童 Web 小说工作区

把小说工作区部署在 NAS 后，可在电脑、iPad 和手机上打开同一个作品。当前源码版本为 `0.2.0-dev.10`，使用 Web SQLite schema 18。已发布的离线镜像 `v0.2.0-rc.1` 使用 schema 11。离线载入见 [v0.2.0-rc.1 发布说明](RELEASE.md)。

| 能力 | 可用操作 |
| --- | --- |
| 写作 | 管理作品目标、设定、人物卡、连载状态与关系、蓝图、章节、剧情线索与伏笔 |
| 编辑 | 查找替换、历史版本、定稿重开、自动保存、断网草稿及多设备冲突对比 |
| AI | 模型预设与诊断，规划设定、人物和蓝图，批量蓝图、写前细纲、单章和批量写稿、选段编辑、逐条审稿和修稿、定稿人物变化候选 |
| 资料 | 参考小说的逐章拆解、整书归纳和仿写 Skill，项目内关键词和可选语义索引 |
| 迁移 | TXT／Markdown 单章，TXT／Markdown／EPUB 整稿，桌面 `.ainovel`，合并 TXT／Markdown，分章 Markdown ZIP，作品 JSON 备份 |
| 运维 | Compose、在线整库快照、新数据卷恢复 |
| 剧本改编 | 从小说定稿建立短剧或漫剧分集，编辑结构化场次、确认剧本和导出 Markdown |

日常写作可直接使用。AI 和语义检索各自配置模型，互不依赖。 [部署与备份](#fnos-部署) · [编辑和写作流程](#保存与-ai) · [资料检索](#参考资料语义检索) · [桌面作品迁移](#从-pagekin-桌面版导入) · [实施进度](https://github.com/ChenMartin/Pagekin/blob/codex/web-novel-fnos/docs/research/nas-web/07-implementation-progress.md)

## 本机启动

使用 Node.js 24。在 PowerShell 中从本目录执行，访问 http://127.0.0.1:3100。直接启动可使用普通文本编辑器。

```powershell
$env:APP_PASSWORD = Read-Host "设置一个至少 12 字符的访问密码"
$env:APP_SECURE_COOKIE = '0'
node server.mjs
```

本机数据默认位于 `web-novel/data`。通过 `APP_DATA_DIR` 可指定独立目录。一个数据目录对应一个运行实例。

从源码在本机启用 EPUB 导入时，在启动前运行 `npm ci --omit=dev --ignore-scripts`。如需同时使用增强编辑器，运行 `npm ci --ignore-scripts` 和 `npm run build:editor`。Docker 构建会安装依赖并生成编辑器资源，首次构建需访问 npm registry。设置 `APP_EDITOR=plain` 可为输入法兼容排查启用普通文本编辑器。

## fnOS 部署

在 J5005 的 `linux/amd64` Docker 主机上，将本目录作为 Compose 项目，复制 `.env.example` 为 `.env` 并填写密码。在目录中执行以下命令。

```sh
docker compose up -d --build
docker compose ps
```

常用 `.env` 配置如下。

| 配置 | 用途 |
| --- | --- |
| `APP_PASSWORD` | 至少 12 个字符的访问密码 |
| `APP_ORIGIN` | 浏览器实际访问地址，包括协议和非默认端口 |
| `PAGEKIN_BIND` / `PAGEKIN_PORT` | 宿主机监听地址和端口，默认 `127.0.0.1:3100` |
| `APP_SECURE_COOKIE` | HTTPS 下保留默认的 `1`。可信局域网 HTTP 联调可设 `0` |
| `PAGEKIN_VOLUME` | 数据卷名，升级时沿用 |
| `APP_EDITOR` | 默认 `auto`，兼容排查时可用 `plain` |
| `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` | 可选文字生成模型 |
| `EMBEDDING_BASE_URL` / `EMBEDDING_MODEL` / `EMBEDDING_API_KEY` | 可选参考资料语义模型 |

Compose 默认监听 NAS 宿主机的回环地址。用宿主机上的 HTTPS 反向代理转发到 `127.0.0.1:3100`，将 `APP_ORIGIN` 填为浏览器实际使用的 HTTPS 地址。若代理运行在容器内，可将代理接到同一个 Docker 网络并转发到 `pagekin:3100`。

反向代理需要允许项目事件流持续连接。对 `/api/projects/<id>/events` 关闭响应缓冲，将读取超时设置为至少 60 秒。服务每 15 秒发送一次保活消息。

受信任局域网内临时联调时，可将 `PAGEKIN_BIND` 设为 NAS 的内网地址，`APP_ORIGIN` 设为实际 HTTP 地址及端口，`APP_SECURE_COOKIE` 设为 `0`。HTTP 会明文传输密码和正文，正式使用请配置 HTTPS。

作品和登录会话存放在 `PAGEKIN_VOLUME` 指定的命名卷，默认名称为 `web-novel_novels`。升级时保留原卷名和 `.env`，避免换目录后连到空库。若已有测试部署，先确认旧容器的实际数据卷名称，再填入 `PAGEKIN_VOLUME`。应用内 JSON 备份适合单部作品，恢复上限为 24 MB。整库备份可在服务运行时生成。

从 `v0.2.0-rc.1` 升级到当前源码前，先生成并复制一份 schema 11 整库快照。从同一 Compose 目录重新构建后，服务启动时会自动升级到 schema 18，保留原定稿和批量写稿任务。若需回退，使用 schema 11 快照恢复到独立卷，再启动原镜像。

## 整库备份和恢复

在 NAS 的 Compose 目录执行。快照文件名应选未使用的名称，建议复制一份到 NAS 之外。

```sh
docker compose exec -T pagekin node maintenance.mjs backup /data/backups/before-upgrade.sqlite
docker compose exec -T pagekin cat /data/backups/before-upgrade.sqlite > before-upgrade.sqlite
```

整库恢复使用新的空数据卷。先备份并停止原服务，然后运行下面的命令。确认返回的作品数量符合预期后，将 `.env` 中的 `PAGEKIN_VOLUME` 改为新卷名称，再启动服务并重新登录。

```sh
docker compose stop pagekin
PAGEKIN_VOLUME=web-novel_novels_recovered docker compose run --rm --no-deps -T pagekin node maintenance.mjs restore < before-upgrade.sqlite
```

确认结果并更新 `.env` 后，再执行 `docker compose up -d --no-build --pull never`。恢复工具会检查数据库版本和完整性，并清除恢复副本中的旧登录会话。原卷保留，可停服务后换回原卷。若回滚涉及数据库升级，应同时使用升级前的快照和相应版本的镜像。

首次部署后，用电脑和另一台设备分别打开同一测试章节。先在电脑保存，确认另一台收到新版提示，再在两端修改同一章，核对冲突对比中的两份正文。最后重启 Compose 服务，确认作品和历史版本仍能打开，并做一次备份恢复。iPad 和手机可一并验证中文输入、旋转屏幕和切回前台后的保存。

## 书房和创作导航

开发分支在页头提供“书房”和“设置”。打开作品后，可从“作品概览”查看设定、人物、蓝图及正文进度。左侧的四个创作阶段可直接切换，当前作品会记住各阶段最近打开的文档。正文目录可以按草稿或定稿筛选，同章的蓝图与正文可从编辑器工具栏互相打开。缺少对应文档时，可按当前章号新建。

“运行中心”按作品查看进行中的章节任务和最近 50 条历史。点击记录会打开对应章节和结果，也可从这里进入批量写作记录。设置提供本机主题、正文字号及模型配置状态。写作时可收起侧栏进入专注模式。

“写作目标”可填写题材、子题材、目标读者、写作语言、目标总章数和单章字数。字段均可留空，目标不会限制可创建的章数。保存到 NAS 后用于本作品的 AI 任务，可在发送内容预览中核对。并发保存会显示 NAS 最新值。作品 JSON 和从新版转换工具生成的桌面导入副本可携带这些字段。

## 保存与 AI

正文上方可打开“查找／替换”，也可按 Ctrl+F 或 Cmd+F。支持跳到上一处或下一处、区分大小写、替换当前或全部匹配。替换按普通文本处理，全部替换会显示确认；继续编辑前可通过“撤销替换”还原最近一次替换。定稿允许查找。正文可用“上一章”和“下一章”切换，未同步稿件沿用本机草稿保护。

构建增强编辑器资源后，正文默认使用 CodeMirror 6，提供 Markdown 语法高亮、自动换行和键盘撤销／重做。切换文档会重置编辑器内的撤销记录，各章持久化版本可从“历史版本”查看。

编辑时写入 IndexedDB 本机草稿。停止输入约 1.5 秒后提交，前台持续输入每 10 秒兜底提交。状态栏在收到服务器确认后显示已保存到 NAS。断网重新连接会重试。刷新后打开对应文档，点“查看本机草稿”比较和恢复。同一章节被另一设备更新时，界面提示比较两稿，服务端保留较新的版本，直到作者选择如何处理。

其他设备保存后，已打开的章节会显示“NAS 上有更新，查看最新版本”。点击可加载新版。有未同步编辑时会保留本机稿，并提供冲突对比。短暂掉线后可补收事件，超出保留窗口时重新读取目录和版本。书名可在作品菜单中修改。

在 `.env` 中配置 `LLM_BASE_URL`、`LLM_MODEL` 和所需的 `LLM_API_KEY` 后，可使用 AI 工作流。模型服务需支持 OpenAI Chat Completions 的 SSE 流式响应，地址填写 API 根路径，例如 `https://api.openai.com/v1`。携带密钥的模型请求要求 HTTPS。模型收到当前文档、作品写作目标及本次选取的作品资料。

打开设定、人物卡或章节蓝图，可生成当前文档的 AI 规划。在运行中心或文档内查看候选，对照原文后确认应用。也可在蓝图阶段选择“批量生成蓝图”，输入连续的章号范围，每次 1–20 章。缺失的蓝图会建立空文档，已有内容或排队后已编辑的蓝图会跳过。相邻前章生成的候选用于衔接，批次支持暂停、继续或取消。建议按章号核对并应用候选。

在“设定与架构”阶段点击“架构模板”，可创建故事前提、人物群像、世界观和情节大纲文档。每个模板提供可编辑的 Markdown 提纲。生成架构候选时可选整体或一个模块，预览可核对范围和发送内容。候选确认后替换当前整份文档，建议每个模块使用独立文档。

在未定稿正文中选中文字，再打开“选段 AI”，可续写、润色、扩写或改成对话。续写会在选段后插入，其他操作会替换所选片段。预览中可比较整章；确认时服务会核对选段位置、正文版本和模型输入来源。

可直接写稿，也可先点击“生成写前细纲”，检查结果后选择“将此细纲用于写稿”。细纲和正文候选是分别保存的任务。可以从任务历史重新打开细纲，在“预览发送内容”中核对写稿输入。选用时会检查当前章节版本、蓝图、前文、伏笔、参考资料和作者要求。任何绑定内容变化后，可重新生成细纲或取消引用。审稿只使用当前正文和实际资料。

任务在 NAS 上执行，浏览器轮询已保存的结果。AI 写稿及修稿输出先保留为候选，应用时校验正文和引用资料版本。服务重启会保留已收到的输出，任务标为中断。

在作品菜单打开“批量写作”，每批可选择 1–20 个空白且未定稿的章节，并填写通用写作要求。NAS 按章号一次生成一章，关闭页面后也会继续。相邻上一章的候选可作为未定稿的衔接参考。逐章确认候选后再定稿，定稿或编辑前章可能使后续候选的来源失效。

批次可暂停、继续或取消。暂停会中断当前请求。模型失败或服务重启后，从批次列表手动继续。若未完成的候选还有完整句段，且生成资料一致，可以从该处续写。其他情况下重新生成未完成的章节。排队期间被修改的章节会跳过，原稿保留。作品 JSON 保留候选，整库快照也保存批次进度。

单章写稿或修稿中断后，从任务历史打开候选。如果有可复用的完整句段，可以点“从完整句段继续生成”。续写保留已完成的前缀，末尾未完成的文字留在原任务。服务端从候选末尾接写，去除能精确匹配的重复片段，另存合并后的候选。正文、生成资料或 Skill 变化后，需重新生成。跨服务重启的续跑依赖当前整库；作品 JSON 恢复保留候选和来源关系。

在作品菜单打开“写作 Skill”，可粘贴提示词或载入本机 UTF-8 的 `SKILL.md`、Markdown 或 TXT 文件，核对后安装。每部作品最多 40 个，每个最多 8000 字符。分别为细纲、写稿、审稿和修稿选择 Skill，实际文本可在“预览发送内容”核对。导入以文本为单位，引用的资料可由作者合并到文本中。作品 JSON 包含已安装的文本和绑定。

Skill 使用作品级绑定。AI 规划沿用细纲 Skill，选段续写沿用写稿 Skill，其他选段编辑沿用修稿 Skill。批量写稿和批量蓝图分别固定创建时的写稿与细纲 Skill。若绑定变化，批次会暂停，可恢复原绑定后继续。候选应用时也会检查生成时用到的绑定。

“审稿”会列出问题、严重程度、引文、原因和建议改法。引文按发起审稿时的正文快照核对。唯一匹配的引文可以定位到编辑器，也可以勾选后加入可编辑的“修稿要求”。引文重复或缺失时保留意见供阅读。若正文已更新，可在任务历史中查看报告，再对当前版本重新审稿。旧任务或模型返回的纯文本也可继续查看、选中并加入修稿要求。调整修稿要求后点击“修稿”，预览生成的候选再决定是否应用。

修稿完成后，点“预览并应用候选”，逐项查看原稿和修稿的插入、删除或替换。起初所有改动都未勾选，翻页时会保留选择。连续的拆段或合段可能归在同一项。点“应用选中的改动”后，服务端保留未选部分的原文和格式，并将合并结果保存为新版本。合并前的正文可从“历史版本”查看或恢复。章节或生成时引用的资料发生变化后，请按当前版本重新生成修稿。

用“预览发送内容”检查本次模型输入。字符预算来自所选预设，默认 64,000，可用 `LLM_CONTEXT_CHARS` 调整。模型自身的 token 上限仍适用。预览和正式任务都保留当前正文全文，按预算取本章蓝图、最近定稿节选、选定资料、相关伏笔及人物设定。若正文和作者要求本身已超出预算，服务会在发起模型请求前提示。

在“参考资料”中导入 UTF-8 TXT 或 Markdown。“搜索作品”按标题或原文检索本作品的正文、设定、人物、蓝图与资料。打开未定稿章节后可选最多五份参考资料用于本次 AI 任务，每份最多取 1500 字符。可填定位词提取匹配位置附近的内容，并在预览中检查。作品备份包含参考资料。

## 模型预设与诊断

原有 `LLM_MODEL`、`LLM_BASE_URL`、`LLM_API_KEY` 配置在设置页显示为“Compose 环境变量”。可在 NAS 用 `LLM_PROFILES_JSON` 或 `LLM_PROFILES_FILE` 增加预设，两者任选一种。重启服务后，在“设置 → 模型预设与诊断”测试连接并保存选择，选择在整个工作区生效。

`LLM_PROFILES_JSON` 可以在 `.env` 中填一行 JSON。例如使用 NAS 可访问的 OpenAI 兼容接口：

```dotenv
LLM_PROFILES_JSON='[{"id":"local","label":"本地写作","baseUrl":"http://192.168.1.10:11434/v1","model":"my-model","contextChars":48000}]'
```

也可把同一个 JSON 数组写到 `model-profiles.json`。在 `.env` 中设置 `LLM_PROFILES_FILE=/run/pagekin/model-profiles.json`，并通过 `compose.override.yaml` 将文件只读挂载到该路径。文件需要对容器内运行服务的 `node` 用户可读。

```yaml
services:
  pagekin:
    volumes:
      - ./model-profiles.json:/run/pagekin/model-profiles.json:ro
```

预设可填写 `apiKey`，含密钥的地址须使用 HTTPS。密钥由 NAS 读取，浏览器接口只返回预设名称、模型名和字符预算，作品备份只记录任务引用。保留稳定的 `id`，便于更新显示名称或轮换密钥。写作模型诊断检查流式正文，语义模型诊断检查现有 `EMBEDDING_*` 配置的向量响应。两者发送固定测试文本。

新任务使用当前选中的预设。已创建的写作、蓝图和参考书队列以及分段续写使用原预设。原预设的地址、模型名或字符预算变更后，续跑会要求恢复配置或新建任务。升级前创建的任务沿用 Compose 环境变量配置。

## 参考资料语义检索

在 `.env` 填写独立的 `EMBEDDING_BASE_URL` 和 `EMBEDDING_MODEL`，需要密钥时填写 `EMBEDDING_API_KEY` 并使用 HTTPS。地址填写兼容 API 的根路径，如自建服务的 `/v1`。服务请求 `POST /embeddings`，使用文本数组与浮点向量响应。[Embeddings 接口](https://developers.openai.com/api/reference/resources/embeddings/methods/create)

重启后打开作品里的“资料语义检索”，点击“建立或继续索引”，再描述要找的资料。索引只处理当前作品的参考资料，每批最多 128 个片段，每部作品最多 2048 个片段。成功的批次会保存在 NAS，失败或重启后可手动继续。切换模型或地址后需要为新配置建立索引。引用结果时可把命中的原文片段加入章节的 AI 输入，再从预览核对。

仅点击索引或查询时会向配置的语义模型发送资料片段或查询文本。章节正文不会自动进入这个索引，关键词搜索可独立使用。作品 JSON 备份保留原始资料，恢复为新作品后可重新索引。整库 SQLite 快照包含已有索引。

在“剧情线索与伏笔”中记录埋设章、预计回收章和实际回收章，按计划埋设、待回收、已回收和已归档筛选。写稿、审稿和修稿可读取当前章相关的线索，旧候选在所引用的线索变化后需重新生成。作品备份包含线索和回收记录。

## 长篇进度

在作品菜单打开“长篇进度”，同表查看每章的蓝图、正文和线索。正文区分空稿、草稿、已定稿和定稿后重开，重开章节已有的定稿仍计入总数。每页显示 30 章，支持输入章号跳转和定位首个未定稿章。可直接打开蓝图或正文。

“线索待核对”根据埋设章、预计回收章、实际回收章和已有定稿提醒作者。预计回收章已定稿与已越过该章但中间有缺章会分别提示。点击提醒可以编辑线索，保存后回到原页。提醒来自章节和线索记录，是否实际埋设或回收由作者核对。

## 人物连载

从作品工具进入“人物连载”，或从人物卡、已定稿正文打开“人物状态与关系”。先选人物，再选开篇或某章定稿后的时间点。状态字段包括位置／阵营、能力、身体、心理、道具和近期事件。关系指向已有的人物卡，改名后仍能关联。选好时间点后，可以查看并按人物筛选该位置有效的有向关系。

每个人物在每个定稿版本上可保存一份状态和关系。首次填写某个位置时可从之前的有效记录带入，保存会确认整份表单，留空表示当时没有该条状态或关系。重新打开定稿编辑期间，已保存的定稿仍是来源。产生新定稿后，旧来源记录移至历史，并从后续章节的当前状态计算中退出。可查看旧记录，核对后在新定稿上重新记录。

生成第 N 章蓝图或正文、审稿和修稿时，会读取第 N 章之前最近的有效人物记录，开篇状态也可用。引用的记录发生变化后，需要重新生成候选。作品 JSON 和整库备份均保留人物记录、历史定稿引用和人物关系。

配置写作模型后，在某章定稿后的人物状态表单展开“AI 人物变化候选”。可预览发送内容，再从该版定稿提取所选人物的六类状态变化。章节重开时依然读取已保存的定稿。结果会标明引文是否唯一匹配，只有唯一匹配的候选提供填入按钮。请再核对引文是否确实支持变化，然后保存人物状态。原文引用随已采纳字段保存；手动改写该值后，可重新核对引文再采用。人物关系继续由作者维护。

已保存的候选可从人物状态表单或作品运行中心打开。重新定稿后，历史候选仍可查看。作品备份会保留任务、已保存引文，并在恢复时重建定稿和人物引用。

## 参考小说与仿写

在作品的“参考小说与仿写”入口导入 UTF-8 TXT、Markdown 或未加密的 EPUB。每份文件最多 8 MB、500 节，按书中顺序编号，保留识别出的原章号和标题。导入预览可核对拆分，书架内可读原文。原书单独存放，作品正文、关键词库和语义库继续使用各自的数据。

“整书自动拆解”从第一个未覆盖的位置开始，每次处理最多 1–20 节，并根据模型上下文缩短区间。已完成的范围报告会直接计入覆盖。队列在 NAS 串行运行，关闭浏览器后可从书架回看。可暂停或取消；失败和服务重启会暂停，点“继续整书拆解”会重新处理未完成的区间。作品备份保留全部范围报告及每本参考书的最新队列，恢复中的活动队列以暂停状态打开。全部位置覆盖后，可另行启动整书归纳。

每次可拆解连续 1–20 个位置。发起前可以预览模型输入。较长章节取开头、中段和结尾的节选，报告包含逐节摘要、逆向蓝图、区间结构、文风和可迁移的写法。覆盖进度按成功报告计算，打开参考书会定位到下一个尚未拆解的位置。所有位置均有报告后，可从已完成的范围摘要生成整书归纳。模型上下文较小时会缩短摘要。任务在 NAS 执行，可取消并回看历史；中断后可重新提交相同范围。

点击“核对写法并保存为 Skill”，可编辑报告中提取的写法。请去除不希望带入作品的原书情节、设定、人名和原句。安装后，到“写作 Skill”手动绑定所需阶段，才会进入该阶段的模型输入。作品 JSON 与整库备份均保留参考书和报告。参考书较多时可使用整库快照，作品 JSON 恢复受 24 MB 上传限制。

## 剧本改编

在作品菜单点“剧本改编”，新建短剧或漫剧项目，选择画幅和单集目标时长。新建剧本集时填写季号、集号和标题，并选取 1–20 章已定稿的小说。每集关联选取时的定稿版本，打开“读原文”可以查看那一版。后来编辑或重新定稿会出现“小说来源已更新”提示。

可逐场填写内外景、地点、时间和对应原文章节，添加动作、对白、括注、转场、字幕与注释。对白可关联作品人物卡，也可手填说话人。输入自动暂存到当前浏览器，点击“保存剧本到 NAS”后其他设备可以打开该版本。遇到版本冲突，可重新读取 NAS，再比较并加载本机稿。

填写完整后点击“确认剧本”，随后可导出 Markdown 或重开编辑。“剧本历史”可查看此前保存的场次，草稿状态下可恢复为新版本。作品 JSON 和整库快照都包含剧本及其历史，作品 JSON 恢复会为新副本重建章节和人物卡的引用。

## 从 Pagekin 桌面版导入

用 Pagekin 桌面版导出作品备份，在 Web 书房点击“恢复备份”并选择 `.ainovel` 文件。支持 Pagekin 原始归档格式 v1 和桌面数据库 schema 7–9。单个归档上限为 48 MB，转换后的作品上限为 24 MB。通过 HTTPS 反向代理访问时，代理的上传限制也要允许对应大小。导入时会检查归档清单、各文件校验值和数据库版本，然后创建独立的 Web 作品。

如果手上只有项目文件夹，可以退出桌面版，从本目录用转换工具处理其中的 `.ai-novel/project.db`，再在 Web 书房恢复生成的 JSON。

```powershell
node desktop-copy.mjs 'D:\作品\我的小说\.ai-novel\project.db' '.\我的小说-Web.json'
```

两种方式都导入设定、人物卡、蓝图、正文和草稿历史，保留定稿与重开稿的关系。头像、桌面知识库、模型配置和运行记录需另行处理。数据库文件仍有 WAL 或回滚日志时，转换工具会提示关闭桌面版后重试。原归档和源数据库可继续在桌面版使用。

桌面数据库 schema 9 中的人物状态和关系事件可以从“人物连载 → 查看桌面人物历史”按人物分页查看。作者记录和已采纳值保留原来的生效章，定稿派生值从相应章写完后生效。关联的定稿被替换后，派生值退出后续写稿上下文，历史仍显示原值及可核验的引文。已移除或无法关联到人物卡的记录可单独筛选。桌面数据库 schema 7–8 可迁移已有状态值和按人物 ID 绑定的关系，作为最后确认进度之后的基线。尚有原文文字但缺少人物 ID 的旧关系，继续保存在人物卡中供核对。

Web 手工保存的人物状态在对应位置优先；之后生效的桌面变化只更新涉及的字段或关系。作品 JSON 备份也保留桌面人物历史及原文版本的引用。需要为此前已导入的作品补回桌面历史时，用原桌面备份重新导入为一个作品副本。

从 `v0.1.0-rc.2` 升级前，先导出一份 schema 10 的整库快照。新镜像启动时将原数据卷升级到 schema 11，保留作品、正文及历史。回退时将升级前的快照恢复到独立数据卷，再用旧镜像和旧 Compose 配置启动。 [升级步骤](RELEASE.md#从-v010-rc2-升级)

## 导入 TXT、Markdown 或 EPUB 整稿

在作品里点击“导入整稿”。UTF-8 TXT 和 Markdown 可识别“第十二章”“第 12 章”“Chapter 12”等独立标题。EPUB 按书内阅读顺序提取正文，同一正文文件内仍可按标题拆分。无章号的 EPUB 正文保留书内标题，可使用连续编号。预览可展开查看每章开头、逐章勾选，选择保留原章号或从指定章号连续编号。首个章标题之前的文字归入首章。

EPUB 在 NAS 上解析，预览确认后才保存。提取范围为正文文字，排版、图片和音视频保留在原 EPUB 中。加密正文、损坏归档、超过解析上限的文件会提示错误。 [EPUB 阅读顺序规范](https://www.w3.org/TR/epub-33/#sec-spine-elem)

导入后的章节为草稿。若提交时有章号被占用，整批撤回，可调整编号后重试。同一份预览在连接中断后按原选择重试，会复用原回执。每次可选 1–500 章，文件上限 8 MB，单章上限 180,000 字符。

## 导出正文

在“文件与备份”中选择“导出正文”，可以下载合并 Markdown、UTF-8 TXT 或分章 Markdown ZIP。默认导出每章最近一次定稿，章节重开编辑后仍可导出该定稿。选“全部章节”会导出 NAS 保存的当前正文，包括草稿。ZIP 按章号命名并排序，上限为 64 MiB。需要同步其他设备上的当前编辑时，等保存状态显示已提交至 NAS 后再导出。

node --test smoke.test.mjs
